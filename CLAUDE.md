# T-MINUS «Покажи один раз» — правила для Claude (читать первым)

Ты помогаешь школьной команде из 3 человек на хакатоне GAMBIT 2026, трек «AUTOMATE IT!».
Делаем 2D-браузерную игру, где автоматизация — ядро геймплея.
**Дедлайн: 12 ноября 2026, 23:59 по Актобе (UTC+5).** С 12.11 18:00 — только исправление багов.

У каждого человека свой Claude и своя роль. Твоя роль описана в `docs/roles/<роль>.md` —
прочитай его сразу после этого файла. Потом прочитай `src/types.ts`: это контракт между ролями.

## Игра в двух словах

Степной космодром, до старта ракеты T−3:00. Игрок один, план вручную не выполнить.
Он нажимает на док робота и **один раз сам показывает работу** (репетиция в копии мира, пошагово):
стрелки — шаг, E — взять/положить, Пробел — подождать. Вернулся на док — петля замкнулась.
**Запись превращается в программу из блоков**, робот крутит её по кругу в настоящем мире.
Дальше игрок правит программу (удаляет шаги, вставляет ДАТЧИК вместо слепого ожидания),
добавляет копии роботов, покупает полку-буфер и второй пресс, смотрит телеметрию и ищет узкое место.
План выполнен — ракета стартует. 6 уровней, последний — бесконечный.

Предметы: `ore` (руда) → пресс → `plate` (пластина); `plate` + `fuel` (топливо) → сборщик → `cell` (ячейка) → стартовый стол.

**Главный урок игры:** робот без датчика работает «вслепую» и промахивается, если машина не готова;
с датчиком — с обратной связью. Плюс время цикла, такт и узкое место.

## Стек

- Phaser **3.90.0** (не v4), TypeScript 7 (strict), Vite 8, Vitest 5, Node.js 20.19+.
- Холст 1280×720, `Phaser.Scale.FIT`. Клетка 64 px. Графика — плоский минимализм, почти всё рисуется
  кодом (`Phaser.GameObjects.Graphics`), иконки и ракета — PNG от C.
- Хостинг: GitHub Pages (через Actions) + itch.io. В `vite.config.ts` стоит `base: './'`.
- В `tsconfig.json` включено `verbatimModuleSyntax`: типы импортируй как `import type { … }` или `import { type X }`.

Команды: `npm install` · `npm run dev` (игра на http://localhost:5173, песочница симуляции — `/debug.html`) ·
`npm test` · `npm run build`.

## Контракт: `src/types.ts`

Это единственный источник правды о типах — **прочитай файл целиком**, там подробные комментарии.
Симуляция ничего не знает про Phaser. Экран рисует игру только из `snapshot()` и меняет мир только
методами `ISimulation`. Менять `types.ts` может только A и только после сообщения в чат команды.

```ts
import { Simulation } from './sim';
const sim = new Simulation();
sim.loadLevel(level, defs);        // LevelData + MachineDef[]; бросает LevelError с понятным текстом
```

| Группа | Методы `ISimulation` |
|---|---|
| Репетиция | `beginTeach(dock, replaceRobotId?)` · `teachInput('up'｜'right'｜'down'｜'left'｜'act'｜'wait')` · `canFinishTeach()` · `finishTeach()` · `cancelTeach()` |
| Роботы | `checkProgram(id, blocks)` · `setProgram(id, blocks)` · `copyRobot(id, delaySteps?)` · `removeRobot(id)` |
| Покупки | `canBuy(type, x, y)` · `buy(type, x, y)` · `sell(machineId)` |
| Время | `start()` · `step(dtSeconds)` → события · `snapshot()` |
| Сохранение | `serialize()` · `deserialize(json)` · `getLevel()` |

Что важно знать про поведение (всё покрыто тестами в `src/sim/__tests__`):

- **Время.** 20 тиков в секунду, один блок программы = 5 тиков (0,25 с). `step(dt)` сам копит дробное время;
  `snapshot().alpha` — доля тика для плавной отрисовки: рисуй робота в `px + (x - px) * alpha`.
- **Режимы** `snapshot().mode`: `plan` (до старта) → `running` → `won`/`lost`; `teach` — идёт репетиция.
  В `teach` снимок показывает **копию** мира, настоящий мир стоит на паузе.
- **Репетиция.** Каждый принятый `teachInput` — один шаг: игрок действует, копия мира проживает 5 тиков.
  Отказ (`ok: false`, причина в `reason`) ничего не записывает и не тратит время: `bump` — упёрся,
  `nothingToTake` — машина ещё не готова (надо ждать Пробелом), `cannotPut`, `noMachine`, `tooLong`.
  Вернулся на док → `canFinishTeach()` → `finishTeach()` создаёт робота. Робот повторяет запись тик в тик.
- **Движение.** Шаг в стену или машину — это поворот к ней. Взять/положить действует на машину **перед** роботом.
  Роботы проходят друг сквозь друга; на одном доке может быть несколько роботов.
- **Промах.** Если взять/положить не вышло, робот теряет шаг и идёт дальше. Блок `sense` (ДАТЧИК) ставится
  прямо перед `take`/`put` и ждёт, пока действие сможет сработать (не дольше 10 с).
- **Машины строгие:** в прессе и сборщике одна порция за раз — пока идёт работа или готовое не забрали,
  новый вход не принимается. Склад и бак стартуют полными. Полка — очередь на `capacity` предметов.
- **Правка программы** вступает в силу с начала следующего круга (`RobotView.pendingProgram`). Программа обязана
  возвращаться на док, иначе `notClosed`. Ставить машины на клетки, по которым ходят роботы, нельзя (`onPath`).
- **Энергия.** Робот — `robotCost`, робот с датчиком — ещё `sensorCost`, машина — `cost`. Удаление и продажа возвращают энергию.
- **Звёзды:** 1 за план + 1 за экономию (`starEnergy`) + 1 за скорость (`starTimeLeft`).
- **Телеметрия:** `RobotView.timeline/cycleTime/usefulShare`, `MachineView.utilization`, `throughput`, `requiredRate`,
  `bottleneck { kind, id, reason }`.
- **События** `step()` плоские: `{ type, x, y, robotId, machineId, item, value }`; у действий игрока в репетиции
  `robotId === OPERATOR_ID`. События от действий игрока (`deployed`, `bought`…) приходят с ближайшим `step()`.
- Тексты отказов и подсказок — по ключам `fail.<reason>` и `bottleneck.<reason>` в `strings/ru.json`.

## Жёсткие требования ТЗ (нарушение = потеря баллов или дисквалификация)

- Только 2D. Работает в Chrome и Firefox на Windows 10/11, 8 ГБ RAM, встроенная графика: **30+ FPS (цель 60), загрузка < 30 с (цель < 5 с), 10 минут без вылетов**.
- **Ноль сетевых запросов во время игры.** Никаких CDN, Google Fonts, аналитики, внешних API. Всё лежит в сборке.
  («Телеметрия» в игре — это внутриигровая панель, она никуда ничего не отправляет.)
- Весь текст, который видит игрок, — **на русском** (казахский — бонус), только через `t('ключ')`.
- Обучение за 60 секунд (уровень 1), понятная цель, победа/поражение/счёт, пауза, настройки, выход в меню, титры.
- School-safe: без 18+, насилия, политики, религии, рекламы, микротранзакций, лутбоксов, азартных игр. Космодром выдуманный, без реальных названий и брендов.
- Ассеты только свои или CC0/CC-BY/OFL, каждый — строкой в `third_party.md`. Вдохновение (The Last Clockwinder, The Farmer Was Replaced, Zachtronics) указываем в README; чужой код и ассеты не берём.
- Не собираем персональные данные. Рекорды — только числа в localStorage, без имён.

## Как работать

- Имена файлов — маленькие латинские буквы, без пробелов (`robot.png`, не `Robot.png`): GitHub Pages различает регистр.
- Любой доступ к `localStorage` — в `try/catch`, игра должна работать и без него.
- Перед коммитом: `npm test` и `npm run build` должны пройти.
- Коммиты маленькие, с префиксом роли: `sim: …`, `ui: …`, `content: …`. Работаем в своей ветке (`sim` / `ui` / `content`), в `main` — через Pull Request на синхронизациях команды.
- Новая npm-зависимость — только через A (он владеет `package.json`).
- **После каждой готовой фичи объясни человеку по-русски в 3–5 пунктах, как она работает и почему так сделано, и допиши эти пункты в `docs/notes-<имя>.md`.** Жюри будет спрашивать любого участника про любой кусок кода — человек должен уметь ответить сам.
- Не делай «всё сразу»: бери следующую задачу из своего брифа, доводи до работающего состояния, коммить.
- Если задача тянет за собой чужую зону — остановись и скажи об этом человеку.
